# The 50 — a 6-hour nonstop plan, 2026-07-29

Inputs: `docs/research-last30days-2026-07-29.md` (what the last 30 days actually
rewarded) and `docs/palantir-reference-2026-07.md` (what the incumbent ships).
Branch: `perf-annotate-sidecars-2026-07-27`. No step requires operator input.

## Objective

Turn a stateless-looking fusion globe into the one thing in this category that
**owns the past, scores what it shows, answers a question, and can be driven by an
agent** — and fix the three operator-reported defects on the way.

## The anti-clone test (applied to every item below)

> Would this change also appear on OSIRIS, Shadowbroker, WorldMonitor, IRONSIGHT, or in
> the Gotham panel inventory?

If **yes**, it is table stakes and only earns a slot when it is on the critical path to
one of the five conclusions in research §8. If **no**, it is a differentiator and gets
priority. Every item carries a one-line `ANTI-CLONE:` note stating which it is and why.

Concretely, we are **not** building: more layers, a prettier command-center chrome, an
AI news-summary panel, a threat-level gauge, or anything whose pitch is "a Palantir
alternative". Those are the commodity (research §1).

## Verification method — defined before starting

Four gates, in this order. A phase is not done until its gate passes.

| Gate | Command | Pass condition |
|---|---|---|
| **G1 unit** | `OSINT_DISABLE_BACKGROUND=1 apps/api/.venv/bin/pytest apps/api -q` | ≥ **2006 passed**, never below the inherited baseline |
| **G2 static** | `pnpm -r typecheck` | clean at every commit boundary |
| **G3 full** | `bash scripts/verify.sh` | green (typecheck + lint + web unit + api) |
| **G4 live** | named per item below | the item's own probe, run **this turn**, output pasted |

**Evidence rule.** No item is reported done without G4 output from this session. Claims
are tagged `proven-live`, `plumbed-unverified` (naming what is missing), or `not-built`.
"Global / complete / full / parity" require a live count. A guard test that passes is
G1 evidence, not G4 evidence — G4 means the behaviour was observed.

**Per-item verify commands are literal.** Where an item says `curl … | jq …`, that
command is the acceptance check for that item.

# PHASE 0 — The three named defects (0:00 → 0:50)

The operator reported these directly; they lead regardless of research ranking.

### 1. Give cached tiers a true age instead of a frozen one
**Evidence:** operator ("OpenSky has so many dead planes and its not fixed yet"); the
code already admits it — `apps/api/app/routes/adsb.py:632` `ponytail: known ceiling — the
OpenSky cache freezes seen_pos_s, so a contact whose fix was fresh at pull can read
"fresh" all day`. Research §4 (fake/stale contacts are the category's top story, 549 pts).
**Files:** `apps/api/app/routes/adsb.py` (`_try_opensky_global`, `_opensky_refresh_once`,
`viewport_filter`).
**Change:** stamp each OpenSky feature with the pull wall-clock at refresh time, and
compute served age as `seen_pos_s + (now - pull_epoch)` for cached tiers. This is the
already-ratified invariant from CLAUDE.md — *"A tier that can serve a CACHE must publish
the age of the DATA, never the age of the response"* — applied to OpenSky exactly as it
already is to the `:8093` AIS sidecar (`last_good`/`age_s`).
**Verify:** `curl -s localhost:8000/api/adsb/global | jq '[.features[].properties|select(.source=="opensky")|.seen_pos_s]|{n:length,min:min,max:max}'` — `max` must grow across two pulls ≥10 min apart, not stay pinned.
**ANTI-CLONE:** differentiator. No competitor computes contact age at all; all render whatever the upstream asserts.

## Sequencing, cut-order, and stop rule

Phases run in order; each ends at its gate and a commit. If a phase overruns, the **cut
order within a phase is bottom-up** (the guard test is written regardless — an untested
change does not ship).

Three items are the designated big swings and may land behind an OFF-by-default toggle
rather than being cut: **6** (viewport loading), **23** (answer substrate), **37**
(inbox). The operator authorised "mostly safe + 3-5 big swings"; these are them.

**Stop rule.** If `bash scripts/verify.sh` cannot be made green, stop feature work and
spend the remaining time restoring green. A red tree at 6 am is worse than 20 items
instead of 50 — and per gate G1 the pytest baseline (2006) must never regress.

**What this plan deliberately does not do:** add a single new data layer. There are 64.
Research §2 shows layer count is not what the audience rewards, and research §1 shows it
is precisely what the commodity competes on.
