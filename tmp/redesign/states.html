States and keyboard

Ease of use is mostly what a surface does when it has nothing to show. This page fixes the four states every panel must have, the one place Escape is handled, and the complete keyboard registry. It is the part of the redesign that is a contract rather than a look.

Four states, because three was not enough

docs/frontend.md:147 already requires loading, empty and error to be three distinct states, and layer-rail/OpsPanel.test.tsx:34 already guards it: a healthy 200 that returns nothing must render a real empty result, and a non-2xx must say unavailable (HTTP <code>) rather than a confident zero. Two persona waves found silent failure anyway, because the real case was missing: degraded, where the surface has some data and is quietly missing the rest.

Escape, in one place

Four separate components bind Escape today and none knows about the others. One handler, one documented order, taken from the existing z-scale. Escape dismisses the topmost live layer and stops.

OrderLayerEscape doesToken
1First-run gatenothing. Onboarding is never dismissed by accident--z-wizard
2Modal or slide-overcloses it and restores focus to whatever opened it--z-modal
3Dropdown or context menucloses it--z-dropdown
4Full-screen appreturns to the map, app state preserved--z-overlay
5Active map toolreturns to Pan and discards the shape in progress--z-dock
6Selectionclears it--z-map

First run

The persona studies found new users do not know where to start, and the reference names Walkthroughs as the Palantir answer. The redesign keeps the existing four-step gate and adds one thing that matters more: the palette affordance is a visible, labelled control in the top bar at all times, so the primary navigation is never invisible.
