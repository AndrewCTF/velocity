Analysis

The reference draws Palantir's split clearly: Contour is tabular and top down, a chain of boards where each board is one step; Quiver is object and time series. Velocity has neither, and it is the largest gap between this surface and the product it borrowed its name from. Both are built from data the platform already holds.

Why this surface is light

Gotham is dark because it is operational: a dark substrate so the only bright thing on screen is data or an anomaly. Foundry is light because it is analytical: tables, schemas, charts and long reading, where a light surface is measurably easier. Palantir ships both, and the mode switch is itself information. When the chrome goes light you are building; when it is dark you are watching.

This costs almost nothing to implement. theme/tokens.css already has a complete light token set, applied by data-theme pre-paint, and it is currently unreachable in the console because the light palette was scoped to a shell that has since been retired.

What Foundry deliberately does not become

Recorded operator decisions, not open questions. Multi-tenant ACL and MLS, distributed compute, streaming change data capture, and connector catalogues are out of scope. Re-opening any of them needs a new decision, not a cleanup.

Scope stays keyless single-operator local SQLite. Everything above is built from data the platform already stores, which is why it fits inside that fence.
